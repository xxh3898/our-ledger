# 제품 원칙

## 1. 빠른 입력

일반 지출은 금액, 소비 주체, 카테고리, 결제 계좌만으로 저장할 수 있어야 한다. 날짜는 오늘, 결제수단은 최근값 등 안전한 기본값을 제공한다. 메모·반복·상세 옵션은 필요할 때 펼친다.

## 2. 자유로운 조회

단순 입력으로 저장한 데이터라도 기간, 주체, 거래유형, 카테고리, 계좌, 금액, 검색어를 조합해 볼 수 있어야 한다. 대시보드와 통계의 숫자는 조건이 적용된 거래 목록으로 drill-down된다.

## 3. 계산의 단일 기준

수입, 소비, 저축, 자산, Goal은 모두 Transaction과 Account Entry에서 계산한다. 별도의 수동 합계 필드를 진실의 원천으로 두지 않는다.

## 4. 개인과 공동의 분리

모든 수입·소비는 `PERSONAL` 또는 `SHARED` 범위를 갖는다. 개인 거래는 Owner가 필수다. 둘은 상대방의 개인 거래를 조회할 수 있다는 전제에 동의한 사용자다.

## 5. 정산하지 않음

Payer는 실제 결제 기록을 남기기 위한 정보다. “누가 누구에게 얼마를 보내야 하는가”를 계산하지 않는다. 제품의 목적은 공동 재무 운영이다.

## 6. 점진적 노출

기능을 삭제해서 단순하게 만들기보다 평소 필요한 정보만 먼저 보여준다. 고급 필터와 설정은 한 단계 뒤에 배치한다.

## 7. 데이터 소유권과 복구 가능성

사용자는 CSV로 자신의 데이터를 내보낼 수 있어야 한다. 서버 데이터는 정기 백업하며 복구 절차를 검증한다.

## 8. 운영 복잡도 제한

2인 서비스에 불필요한 분산시스템을 넣지 않는다. 기능 추가보다 입력 지속성, 계산 정확성, 백업 가능성을 우선한다.
